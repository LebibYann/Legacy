# gwd – GeneWeb HTTP daemon

`gwd` is the standalone HTTP/CGI server that publishes GeneWeb genealogy databases.
It serves dynamic HTML pages (person/family sheets, charts, searches, setup, admin), static assets (images, CSS, JS), performs authentication (wizard / friend / public), handles plugins, caching, background workers, and optional reverse‑proxy/CGI integration.

This document summarizes:

1. Purpose and high level architecture
2. Request lifecycle overview
3. Authentication model
4. Plugin system & lexicon loading

## 1. Purpose and architecture

`gwd` wraps core GeneWeb library modules (database driver, templating, HTML helpers) to expose genealogy data over HTTP. Internally it builds a `printer_conf` (`output_conf`) that maps GeneWeb’s generic output abstraction to web server primitives (status line, headers, body write, flush).

Main subsystems inside `gwd.ml`:

- Argument parsing & configuration accumulation (numerous refs: `selected_port`, `default_lang`, `n_workers`, etc.)
- Optional daemonization (`-daemon`) on Unix.
- Listening socket creation (unless forced CGI) and accept loop with a pool of worker processes / threads (controlled by `-n_workers` / `-max_pending_requests`).
- HTTP parsing (headers, method, multipart form detection with `is_multipart_form`).
- Request routing (person pages, family pages, searches, images, notes, setup redirect, robots.txt, static file copies from etc/assets, plugin endpoints).
- Authentication & session (basic or digest; timeout driven by `login_timeout`).
- Dynamic lexicon / language negotiation (default, requested, browser chosen if `-choose_browser_lang`).
- Plugin loading through dynamic linking (`Dynlink.loadfile`) with safety check via MD5 allow‑list (`GwdPluginMD5`). Assets and lexicon additions of plugins cascade into lexicon cache key (`lexicon_fname`).
- Output templating (`Templ.output_simple`) plus manual fallbacks.
- Logging (`Geneweb_logs.Logs`) and robot/exclusion tracking (`robot.ml`).

## 2. Request lifecycle (simplified)

1. Accept connection (unless CGI mode: read from stdin / environment).
2. Parse request line & headers into `conf.request`.
3. Resolve database name (bname) from URL path; initialize base config (`Config.printer_conf` + base environment).
4. Perform optional redirect (`-redirect_addr`) or address filtering (`-only_addresses`, `-no_host_address`).
5. Language resolution (query parameters > cookie > browser if allowed > default).
6. Authentication check (wizard/friend/public) using `.auth` file and in‑memory nonce for digest.
7. Route: static asset, robots, setup link, database handler (person/family, search, notes), plugin handler, or fallback.
8. Perform DB operations (read person/family, compute relationships) using `Geneweb_db.Driver` helpers.
9. Render template or generated HTML; emit headers then body.
10. Close / recycle connection (keep‑alive may be limited via timeout or robot rules).

Multipart form handling for file uploads uses `is_multipart_form` and boundary extraction (`extract_boundary`).

## 3. Authentication

Two privilege levels beyond public: Friend and Wizard.

- Passwords provided via HTTP Basic (default) or Digest (`-auth_digest`).
- The `.auth` file (path set by `-auth`) controls user credentials and roles; wizard can edit database, friend has elevated viewing rights, public restricted by privacy rules.
- Digest nonce seeded from a server private key file `cnt/gwd_private.txt` (auto‑generated if absent).
- Failed attempts optionally logged verbosely when `-trace_failed_passwd`.
- `-wizard_just_friend` forces wizard accounts to behave as friend (permanent downgrade for browsing sessions).

## 4. Plugins & lexicon

`-plugin` / `-force_plugin` / `-unsafe_plugin` (see code variables `plugins`, `forced_plugins`, `unsafe_plugins`) allow loading dynamic `.cmxs` bundles from specified directories. Each plugin directory structure:

```
<plugin>/plugin_<name>.cmxs
<plugin>/assets/lex/*.txt (additional lexicon entries)
<plugin>/assets/... (static files)
```

Lexicons are merged in loading order (reversed in `rev_iter`) and cached (`load_lexicon`) keyed by language plus plugin sequence to avoid rebuilding on each request. `alias_lang` supports language alias resolution (e.g. `en_GB` -> `en`).

## 5. Concurrency / performance

- `-n_workers N` number of worker processes (or 0 for single process; deprecated `-no-fork` equivalent).
- `-max_pending_requests` limits queued requests awaiting a worker; overflow yields immediate refusal.
- `-conn_timeout` sets per connection activity timeout (seconds).
- Caching: lexicon, language lists, database descriptors, plugin assets; plus optional external cache files generated by `cache_files` binary for search/autocomplete.
- Predictability: `-predictable` sets deterministic mode (affects random tokens used e.g. for nonces/captcha-like features if any).

## 7. Runtime environment & files

Key directories relative to base dir (after `Geneweb.GWPARAM.init`):

- `<base>.gwb/` root of a database instance
	- `persons.gw?` / internal arrays managed by the driver
	- `etc/` configuration (generated `.gwf`, lexicons, particles)
	- `images/` pictures (can be overridden by `-img_dir` / served via `-img_prefix`)
	- `notes/`, `wiznotes/` textual notes
	- `cnt/` counters, generated files (nonce key `gwd_private.txt`)

Lock files: one per base (`gwd.lck`) used during operations altering state (login tracking & redirect logging).

## 8. Logging & monitoring

Logging via `Logs.syslog`, `Logs.info`, `Logs.warn`; configurable verbosity. Robot access patterns recorded, with possible throttling / exclusion.

Password failures: optional verbose logging with referer and user agent when `-trace_failed_passwd`.

Redirects log into lock/adm file for auditing (`log_redirect`).

## 9. Security considerations

- Always prefer Digest (`-auth_digest`) over Basic when running without TLS; ideally terminate TLS in a reverse proxy.
- Use `-only_addr` to restrict admin exposure; avoid `-nolock` in production.
- Keep `gwd_private.txt` secret; regeneration forces clients to re‑authenticate.
- Review allowed tags file to mitigate XSS via notes/wiki.
- Plugins: only load trusted; MD5 gating prevents tampering unless bypassed with `-unsafe_plugin`.

## Examples

Run server on port 8080 with English default, two plugins and Digest auth:

```
gwd -bd /srv/geneweb -port 8080 -lang en -auth_digest \
		-plugin /srv/gw-plugins/stats -plugin /srv/gw-plugins/maps
```

Force CGI mode behind Apache (environment provides SCRIPT_NAME etc):

```
gwd -cgi -gw_prefix /geneweb -lang fr
```

Restrict access to local network, run 8 workers, short login timeout:

```
gwd -only_addr 192.168.1.0/24 -n_workers 8 -login_timeout 900
```

Normally 0 on clean shutdown. Non-zero codes can occur on fatal configuration / binding / plugin load errors.
